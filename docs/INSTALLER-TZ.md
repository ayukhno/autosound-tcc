# ТЗ інсталятора — установка й налаштування autosound

> Технічний бік установки. Продуктове бачення TCC — у `TCC-Concept.md`,
> модель даних — у `TCC-TZ.md`, заявки в репо скіла — у `SKILL-CHANGE-REQUESTS.md`.
>
> Статус: узгоджено на сесії 2026-07-30. Реалізації ще нема.

---

## 0. Що вирішує

Новачок сьогодні не може поставити скіл робочим. Чинний шлях у README
(`/plugin marketplace add` → `/plugin install`) не ставить **Python-залежності**
`rew_tool/` (`numpy`, `scipy`, `matplotlib`), і донедавна в репо не було ні
`requirements.txt`, ні жодної згадки `pip install`. Маніфест доданий 2026-07-31
(SCR-020, `done`) — але ставити його все одно нема кому, поки нема інсталятора.

Точна межа наслідків (перевірено в коді, деталі → SCR-020): `numpy` імпортується
на рівні модуля в п'яти файлах — без нього вони не імпортуються взагалі.
`scipy` і `matplotlib` імпортуються **лениво**, за місцем використання, і дають
зрозумілий `RuntimeError` з точною командою. Тобто це **свідома дієта залежностей**,
і брак «зайвого» коштує однієї фічі, а не сесії.

Робота інсталятора тут — поставити все **наперед**, щоб стіна не приходила
посеред тюна. Це головна причина його існування — сильніша за вибір моделей ШІ.

Другий бар'єр — гроші. Спільнота не готова платити за ШІ, щоб *спробувати*.

## 1. Ключове архітектурне рішення: харнес ≠ модель

> **Застаріло в частині OpenCode (2026-08-13).** Харнесом його не взяли: він не вміє витрачати
> підписку Claude, а вона — основний шлях. Замість нього: Agent SDK для Claude, `omp` для решти
> вендорів. Сама теза «харнес ≠ модель» вціліла і працює далі — модель обирається в пікері TCC
> або прапорцем omp, безкоштовно й скільки завгодно разів, і переїзд з безкоштовної на платну
> не є міграцією. Решта документа чинна.

Раніше «вибрати ШІ» означало: поставити CLI + залогінитись + купити підписку.
Дорого, незворотньо, потребує візарда з матрицею підписок.

**OpenCode розчіплює ці дві речі:**

- **Харнес** (хто *виконує* скіл) — ставиться один раз, скриптом.
- **Модель** (хто *думає*) — рядок у меню `/models`, змінюється за секунду,
  безкоштовно, скільки завгодно разів.

Наслідки, які визначили весь інший дизайн:

- Вибір моделі перестає бути кроком установки. Візард для нього не потрібен.
- Перехід «безкоштовна модель → платний Claude» перестає бути міграцією:
  `/connect` + `/models`. Той самий проект, та сама історія тюна, нуль переустановки.
- OpenCode читає **Claude Code skills без переробки**, скануючи `.claude/skills/`
  і `~/.claude/skills/`. Установка скіла = симлінк. Портування нема.
- Критика можна викликати тим самим бінарем з іншою моделлю
  (`opencode run -m <інший-вендор>`) — крос-вендорний анти-анкоринг збережено,
  вимога скіла «reviewer CLI **outside** the driver session (inside = deadlock)»
  виконується природно, бо це окремий процес.

## 2. Ланцюг установки

```
packaging/macos/install.command      ← чистий bash, нуль Python
packaging/windows/install.cmd        ← чистий PowerShell, нуль Python
        │
        │  git → Python → venv → pip install → opencode
        │  → симлінк скіла → TCC у той же venv
        │  → ~/Autosound/ + CLAUDE.md
        ↓
   cd ~/Autosound && opencode
        │
        ↓
CLAUDE.md (~15 рядків, вантажиться харнесом сам)
   1-й хід: doctor, сирий вивід у чат
   далі: інтейк за скілом → ШІ сам створює ~/Autosound/<авто>/
```

**Порядок жорсткий: примітивне ставить складне, ніколи навпаки.**
TCC — це *дім* інсталятора, не його *рантайм*. Qt-візард у ланцюгу установки
неможливий: PySide6 потребує Python, який ми якраз і ставимо.

### 2.1 Запуск bootstrap — асиметрія по ОС

| ОС | Спосіб | Чому |
| :-- | :-- | :-- |
| macOS | `curl -fsSL … \| sh` | Terminal один, плутати нема з чим. Скачаний `.command` отримав би `com.apple.quarantine` і Gatekeeper-бар'єр — тобто був би **гіршим** за one-liner |
| Windows | `install.cmd`, подвійний клік | Подвійний клік завжди відкриває cmd.exe; перший рядок файла перезапускає себе через `powershell -NoProfile -ExecutionPolicy Bypass`. Двозначність cmd/PowerShell зникає як клас |

Ціна windows-варіанту: Chrome/Edge можуть позначити `.cmd` як «unsafe download» —
один клік «Keep». Прийнято.

Нативні пакети (`.pkg` / MSI) відкинуто на v1: Apple Developer $99/рік + нотаризація
+ підпис у CI — тижні роботи заради усунення одного кліку.

### 2.2 Що робить скрипт (нуль питань користувачу)

1. `git` — перевірка; macOS: Xcode CLT; Windows: `winget install Git.Git`, потім PATH-refresh.
2. Python 3 — перевірка; Windows: `winget install Python.Python.3.11` + **повний рестарт вікна**.
3. `venv` у теці TCC.
4. `pip install` — TCC + залежності скіла.
5. `opencode` — офіційний install-скрипт.
6. Симлінк скіла (§3).
7. `~/Autosound/` + `CLAUDE.md` + два вказівники.
8. **Preflight жорстких блокерів** (§5).
9. Друк двох команд і посилання на матрицю ліцензій.

Питань у shell-фазі **нема жодного**. Причини:

- На macOS `stdin` зайнятий пайпом (`curl | sh`) — будь-який `read` повертає порожньо.
  Лікується `< /dev/tty`, але це клас багів, що ловиться в користувача, не в розробника.
- Меню довелося б писати двічі (bash + PowerShell) і локалізувати.
- Єдиний вибір, який справді цікавий користувачу — **модель** — робиться в
  `opencode` (`/connect`, `/models`), де вже є свій інтерактивний UI.

### 2.3 Ідемпотентність, оновлення, деінсталяція

Той самий скрипт, три режими:

- **без прапорців** — установка; повторний запуск = оновлення (`git pull` + `pip install -U`).
- `--configure` — тільки крок вибору провайдера/моделі.
- `--add-harness <name>` — додати другий харнес (Claude Code / agy), не чіпаючи
  Python, скіл і проекти.
- `--uninstall` — знімає симлінк, venv, TCC, opencode. Для останнього не пишемо своє:
  `opencode uninstall` існує як штатна команда («uninstall opencode and remove all related files»),
  перевірено на 1.18.1.

Ідемпотентність **обов'язкова**, не бонус: установка падає посеред шляху
(мережа, права, quarantine), людина перезапускає. Скрипт мусить переживати
повторний запуск, інакше перше падіння лишає напівстан.

> **Захисне правило: `--uninstall` НІКОЛИ не видаляє теки проектів.**
> Навіть з `--force`. Там вимірювання, зроблені годинами, які не відтворити.

**Пастка деінсталяції:** скрипт видаляє теку TCC, всередині якої сам виконується.
Bash дочитує файл на льоту — видалення посеред роботи дає обрізане виконання.
Фікс: `--uninstall` першою дією копіює себе в temp і перезапускається звідти.

### 2.4 Стаб у теці користувача

`~/Autosound/autosound-setup` — **однорядковий стаб**, що викликає справжній скрипт
усередині встановленого TCC. Не копія: копія роз'їхалася б з апстрімом при першому
ж `git pull`.

## 3. Установка скіла

**Глобально:** `~/.claude/skills/autosound-tuning` → симлінк на submodule
`…/autosound-tcc/vendor/autosound-tuning-skill/skills/autosound-tuning`.

Причини:

- `~/.claude/skills/` — **рідна** тека Claude Code, і OpenCode читає її як сумісну.
  Скіл одразу стоїть правильно для обох харнесів.
- Оновлення: оновив TCC → оновився скіл, автоматично, для всіх проектів,
  включно зі старими в різних теках.
- Проектні симлінки (`<проект>/.claude/skills/`) або дублюють глобальний
  (зайві файли), або вказують на різні копії — і тоді ми відтворюємо матрицю
  версій, яку §4 щойно вбиває.

**Windows:** symlink потребує адмінських прав або Developer Mode. Використовуємо
**junction** (`mklink /J`) — для тек працює без адмінських прав і не ламається
при перезаписі файлів усередині.

## 4. Версія скіла

Submodule TCC — **єдине джерело правди**.

**Правило релізу:** у релізному тегу TCC submodule зобов'язаний указувати на
**тег** скіла, не на гілку. Перевіряється одним рядком у CI. У dev-гілках — куди завгодно.

Тоді «остання версія скіла» і «те, на що вказує submodule», перестають бути
різними речами.

Чому не «завжди останній тег скіла»: `core/vendor_loader.py` імпортує `rew_tool`
напряму — жорстке зв'язування. Новий тег скіла міг би зламати вже встановлений
TCC без жодної зміни в TCC.

> **Формулювання ТЗ уточнено:** інсталятор тягне не «останню версію скіла»,
> а **останню перевірену**.

Поточний стан для довідки (2026-07-30): submodule вказує на `v2.7.0-23-g8cd7086`
(гілка `feat/tcc-sync-p0`), `origin/main` — `v2.7.0-20`, останній тег — `v2.7.0`.
Тобто правило зараз ще не виконується.

## 5. Перевірка — doctor, розрізаний надвоє

Розріз обов'язковий: якщо `pip install` тихо впав, ШІ стартує нормально
(він же в opencode), береться виконувати `CLAUDE.md`, і лише там виявляє, що
`numpy` нема. Пізно — користувач уже вважає установку успішною.

**A. Скрипт, до передачі ШІ:**

Жорсткі блокери — впало, скрипт **вмирає з точним фіксом і не створює теку проекту**:

- `git`, `python3`
- `python3 -c "import numpy"` — єдина тверда залежність скіла
- симлінк скіла на місці
- `opencode` у PATH

Попередження, не блокери — установка триває, але скрипт каже вголос:

- `python3 -c "import scipy"` — без нього не працює розрахунок кросоверів
- `python3 -c "import matplotlib"` — без нього не малюються графіки

Розділення не косметичне: `scipy`/`matplotlib` імпортуються лениво і мають власні
повідомлення з фіксом (§0). Вбивати установку через них означало б бути суворішим
за сам скіл.

**B. ШІ, перший хід за `CLAUDE.md`** — те, що потребує діалогу:

- канал Радника (`--doctor`)
- обраний провайдер/модель, наявність квоти
- стан проекту
- **мапа ролей:** `Generator → opencode/<модель>` · `Critic → <bin>/<модель>`

Не циклічно: драйвер тестує *чужий* канал, не себе.

> **Антидот проти narrated compliance.** `references/core/driver-discipline.md`
> задокументував реальний випадок: change-gate був «згаданий» 70+ разів і
> виконаний **нуль**. Тому в `CLAUDE.md` жорстко: **вивести сирий вивід doctor
> у чат дослівно, перед будь-яким висновком.** Користувач бачить машинний текст —
> підробити не вийде.

**Планка діагностики висока**, бо запасного шляху нема (§10): кожен `✗` іде
разом з готовою командою-фіксом, як у `_gemini_common.sh`.

## 6. Передача ШІ: файли правил у теці проекту

```
~/Autosound/CLAUDE.md    ← канонічний, ~15 рядків, формат Claude
~/Autosound/AGENTS.md    ← 1 рядок: "Read CLAUDE.md in this folder and follow it."
~/Autosound/GEMINI.md    ← 1 рядок: те саме
```

Один канонічний + два вказівники. Не копії (роз'їдуться), не симлінки/хардлінки:
на Windows symlink потребує прав, а хардлінк ламається, коли редактор пише через
«temp + rename» — а Write-інструмент ШІ робить саме так. Тобто лінк дав би тихий
розрив рівно в момент переписування.

**Зміст `CLAUDE.md` (≈15 рядків, не більше):**

1. хто ти в цьому проекті (Генератор);
2. скіл лежить там-то — читай його;
3. перший хід: doctor, **сирий** вивід;
4. далі: інтейк за скілом;
5. стан на диску — джерело правди, не пам'ять;
6. відповідай мовою користувача.

**Обмеження на розмір жорстке.** Auto-loaded файл вкидається в контекст кожного
ходу всю сесію. `references/core/driver-discipline.md:3` прямо каже: вантажити
ці правила драйверу в режимі A «only makes it slow and timid».

**Після успішного doctor ШІ переписує `CLAUDE.md`** у 3-рядкову версію:
«Генератор · скіл тут · стан на диску — істина». Вказівники не міняються ніколи.

Причини саме такого життєвого циклу:

- Лишити 15 рядків назавжди — платити шум кожен хід усіх наступних сесій, і
  гірше: ШІ може вирішити щось переставити на 20-й сесії.
- Видалити повністю — забрати ре-анкор «стан на диску — істина», головний
  антидот проти дрейфу.

## 7. Перший проект

Скрипт створює **тільки корінь** `~/Autosound/` + файли правил. Реальний проект
створює **ШІ або TCC**.

Причина: «перший проект» — це не порожня тека, а `autosound_context.md` з авто,
драйверами, DSP і цілями. Це інтейк, діалог. Скрипт цього знати не може.
У TCC воно вже написане: `ui/tcc/new_project_dialog.py` питає vendor і модель DSP
зі звірянням по `data/dsp_profiles/*.json`.

## 8. Матриця ліцензій — довідковий екран, не розгалуження

Користувач мусить чітко зрозуміти: **підписка на чат ≠ доступ агенту в терміналі**,
і це працює по-різному в різних вендорів.

| Вендор | Що НЕ дає доступу | Що дає | Гроші |
| :-- | :-- | :-- | :-- |
| Anthropic | claude.ai Free | Claude Pro/Max → `claude` через OAuth · або API-ключ | від $20/міс · або per-token |
| OpenAI | — | ChatGPT Plus → Codex CLI · або API-ключ | $20/міс · або per-token |
| Google | підписка на застосунок Gemini | `agy` OAuth (безкоштовний тижневий ліміт) · AI Studio API-ключ (безкоштовно, без картки) · GCP billing | 0 / 0 / платно |
| OpenCode Zen | — | безкоштовні моделі beta-періоду · платні за токени | 0 / платно |
| Локально | — | Ollama | 0, якість на цьому скілі не перевірена |

Три правила:

1. **Ціни й ліміти НЕ зашиваються в білд.** Тягнуться з GitHub, offline-fallback
   з датою («дані на РРРР-ММ-ДД, актуальні тут: <посилання>»). Набір безкоштовних
   моделей Zen змінюється постійно — список тягнути живцем з `/models`.
2. **Кожен рядок має пряме посилання** — щоб користувач сам дослідив безкоштовний шлях.
3. **Візард не веде до платного за замовчуванням.** Показує все, включно з нулями.

Скрипт цю матрицю **не друкує** — друкує одне посилання на веб-сторінку.
Сторінка оновлюється без релізу.

## 9. Правило проекту: жоден ШІ-канал не є припущенням

> **Драйвер, Критик і харнес — три незалежні змінні в одному конфізі.
> Doctor їх показує, скрипт їх міняє, проект про них не знає.**

Мотивація — реальний ризик: вендор може заборонити підписки в сторонніх харнесах
і лишити тільки оплату за токени. Тоді Claude перестане працювати в OpenCode і
доведеться переходити на нативний Claude Code.

Що це коштує при нашому дизайні: майже нічого. §3 (скіл у `~/.claude/skills/`)
і §6 (канонічний `CLAUDE.md`) уже поклали страховку — перехід зводиться до
`--add-harness claude`, `cd ~/Autosound/<авто>`, `claude`. Проект, стан, історія
недоторкані.

Що треба закласти явно:

1. **`.critic-env` з першого дня**, навіть на безкоштовній конфігурації. Це вже
   чинна конвенція скіла. Апгрейд = правка одного файла. Захардкодити модель у
   скрипт = вбити цей шлях.
2. **`CRITIC_BIN` незалежний від драйвера** — `agy|gemini|opencode|claude`.
   Критик іншого вендора переживає заборону в одного.
3. **`opencode_critic.sh` читає модель зі змінної** (як `GEMINI_CRITIC_MODEL`).
4. **Ролі, а не вендори, у станових файлах.** `dsp-state-current.md`,
   `tuning-changelog.md` не містять конфіг моделі. Назва моделі лишається тільки
   в `review-log.md` / `audit-trail.md` — як **походження рішення**, не як налаштування.
5. **Doctor друкує поточну мапу** (§5-B).
6. **Виклик ШІ з TCC — через один модуль.** `core/agent_session.py` уже є; прямий
   `claude-agent-sdk` по коду не розповзається.
7. **Детект вичерпання безкоштовної моделі.** Free-tier Zen ріже контекст до
   **200K** замість рідного 1M. Довга сесія в цю стелю впреться. Скіл має сам
   сказати: «контекст близько до межі — ось що дасть перехід, ось скільки коштує».
   Чесний тригер апгрейду, заснований на факті.

## 10. Мова

Скрипт — **англійською**. Кожне падіння закінчується рядком `Docs: <url>`.

Детект локалі **пишемо**, таблицю мов лишаємо з одним записом (англійська) —
`FAQ.md` існує лише англійською, а `README.uk/de/pl.md` живуть у **скілі**, не в TCC.
Додати мову = один рядок, коли переклад з'явиться.

Чому не 4 мови в скрипті: рядки, продубльовані між bash і PowerShell, помножені
на 4, у файлі, який ми домовились тримати тупим. Плюс перекладена помилка гірше
гуглиться, а команда-фікс однакова всіма мовами.

Мова далі — робота ШІ (§6, пункт 6).

## 11. Свідомо поза обсягом

- **Qt-візард установки.** Після розчеплення харнеса й моделі (§1) візард більше
  не приймає складних рішень — він виконує лінійну послідовність. GUI навколо
  `curl | sh`, `pip install`, `ln -s` не додає користувачу нічого, крім тижнів
  роботи та i18n через Qt Linguist. Наступним кроком вартий GUI лише **екран
  матриці ліцензій + doctor** — там людина читає, порівнює і клікає посилання.
- **Гілка `manual_step-by-step`.** Не фігурує в інсталяторі ніде. Це ручний режим;
  з часом на його основі — окремий режим у TCC.
- **Питання в shell-фазі** (§2.2).
- **Проектні симлінки скіла** (§3). Відтворюваність старого проекту на старій
  версії скіла — потреба розробника, робиться руками.
- **Нативні підписані пакети** (§2.1).

## 14. Тестова матриця

Валідація ділиться надвоє, і плутати їх не можна (R11).

### 14.1 Чистий ноут — ворота релізу

Виконується **після** появи інсталятора, на машині без жодного ШІ-інструменту.
Перевіряє те, чого машина розробника перевірити не може:

- шлях від голої ОС до працюючого `doctor`, обидві ОС;
- чи справді Zen Free працює без акаунта **з невідомого сервісу IP** (R1 перевірено
  лише з машини, що вже користувалась opencode);
- Xcode CLT / `winget` / PATH-refresh / junction — усе, що зараз узято з документації;
- реальний час установки і місце на диску.

### 14.2 Машина розробника — покриття вендорських шляхів

Наявні доступи дозволяють перевірити **всі** гілки §8 без додаткових витрат:

| Доступ | Що розблоковує |
| :-- | :-- |
| Claude Pro | нативний Claude Code як драйвер; `--add-harness claude` (§9); шлях переходу з OpenCode |
| Токен Fable 5 | найкращий за твоїм досвідом драйвер — база для порівняння якості |
| Agy API-ключ | канал Критика через `agy`, незалежний від opencode (§9.2) |
| Підписка Gemini (десктоп) | ручний clipboard-канал як fallback |
| Codex (безкоштовний) | третій вендор для `CRITIC_BIN`; перевірка `.cmd`-дірки (SCR-022) |
| `GEMINI_API_KEY` | `google/gemini-3.1-pro-preview` через opencode — Критик на Gemini Pro **уже працює** |
| Zen Free | безкоштовний старт новачка |

Практичний висновок: **порівняння якості між моделями** (R6) можна зробити тут і
зараз, не чекаючи чистого ноута. Чистий ноут потрібен лише для §14.1.
